# Halo Mega Bloks (Project Haggar) decompilation: design

Status: approved 2026-10-18. Phases 0 (`docs/specs/phase0-results.md`) and 1
(the public launch) are done. Phase 2 has started
(`docs/plans/2026-10-18-phase2-pc-port.md`).

## Goal

People can rebuild *Project Haggar*, the cancelled Halo Mega Bloks game
(n-Space, 2013, Xbox 360, Unreal Engine 3), from source and run it natively:
first on PC, and **eventually on an Anbernic handheld**. Like the Halo 2
decomp, this is a public community project, but without a provenance policy:
names, types and source paths from the PDB are used directly.

**What counts as done (user, 2026-10-18):** n-Space's own code plus its
scripts. The engine is not decompiled by hand. The minimum that gets the game
running natively is a static recompilation of the whole executable plus a
runtime. The decompiled game code and scripts are the readable, moddable layer
on top.

**Effort (user, 2026-10-18):** one lane (Opus 5.5, high effort), at low
priority, "as quick and painless and efficient as possible". Phases run one
after another, without approval gates. The coordinator stops only for steps
the user has to do.

## What we have

All of it is in `../Project Haggar/UE3-STL2/`. The XEX and PDB are copied into
the git-ignored `orig/` as `MegaHaloGame.xex` and `MegaHaloGame.pdb`.

| | |
| --- | --- |
| Executable | XEX2, **devkit-signed** (only the zero key decrypts it), LZX-compressed (window 32 KB). Image base `0x82000000`, image size `0x24C0000`, entry point `0x83ECAA78`. Basefile SHA-256 `af5c3002…940e0b`. XenonRecomp needs the decrypted XEX that `tools/xex.py --decrypted` writes |
| Symbols | A full private PDB (MSF 7.00, 220 MB) |
| Engine | **Exactly UDK July 2012 BETA 2** (engine 10246, changelist 1340247), compiled Oct 18 2013, 32-bit PowerPC (big-endian) |
| Compiler | XDK 21076.11 `cl.exe` 16.00.11886 (each contributor supplies their own) |
| Middleware | Wwise 2012.1.4, Gameware Navigation 2014.0.4, PhysX and APEX, Scaleform GFx, Bink 2, XAudio2 |
| Content | Cooked packages (`.xxx`, `.upk`, `.tfc`), Wwise banks, `Coalesced_INT.bin` |
| Emulation | A Xenia Canary build (Sept 2024) packaged for this game, with devkit XEX support and keyboard passthrough. Its readme reports that it reaches gameplay, with workarounds through the dev menu. Not tested here yet |

### What the PDB gives us

- **215,944 functions** with their names, addresses and sizes, plus 21,455
  library functions that have only public symbols.
- **759,808 type records**, covering class layouts, vtables, enums and signatures.
- **Each object file's compiler command line**, and **no LTCG**: each object
  can be matched on its own.
- **Unity builds**, with line information that maps each function back to its
  original `.cpp` file.
- **Named seams for the port:** the 360 Direct3D library (2,485 functions),
  the UE3 Xenon renderer layer (`XenonD3DDrv`, 1,065 functions), XAudio2,
  kernel imports, and the PowerPC save and restore helpers.

### Where the code is

| Tier | Contents | Functions |
| --- | --- | ---: |
| game | UDKBase, GameFramework, MegaHaloGame, Cognition. **Owner `nspace` 1,258, `epic` 5,808** | 7,066 |
| engine | Core, Engine | 92,662 |
| platform | Xenon* drivers, Launch, IpDrv, OnlineSubsystemLive, GFxUI, GwNavEngine, Grip, AkAudio, XAudio2 glue | 18,324 |
| lib | PhysX, APEX, Wwise, Gameware Navigation SDK, Scaleform, Bink, D3D, XDK libraries, CRT | 97,892 |

- **Tier** comes from the module's path in the PDB.
- **Owner** (game tier only): a native class whose script class is identical
  to UDK's, or modified from it, is `epic`. One with no UDK counterpart is
  `nspace`, and so is anything in MegaHaloGame or Cognition. This is a
  heuristic, and corrections are welcome.

## Approach: three tracks

### Track 1: native port (the deliverable)

1. **Static recompilation with a XenonRecomp fork.** (Phase 2 used the ReXGlue
   SDK's codegen, which is based on XenonRecomp, instead: see "Phases".) Phase 0 translated the
   whole XEX, and sampled output compiles. The fork adds two things this
   compiler needs:
   - this compiler's jump-table pattern (`lis; slwi; addi; lwzx; mtctr; bctr`,
     about 320 sites)
   - the 52 missing instruction types
   The target is zero warnings and a full compile. The function list comes
   from the PDB.
2. **A Xenia-hosted runtime first.** Reuse Xenia's (BSD) kernel and XAM, its
   GPU (Xenos emulation over D3D12 or Vulkan) and its XMA audio, and replace
   only its CPU JIT with the recompiled code. This is the quickest route to a
   running PC build.
   - Its first step is a baseline: does the build boot in the packaged Xenia
     Canary?
3. **A native renderer for handhelds.** Replace the D3D library or the UE3
   Xenon renderer layer with a host renderer (GLES or Vulkan), and translate
   shaders with XenosRecomp or Xenia's translator. Xenia's GPU emulation is
   too heavy for mobile chips, so the handheld needs this.
4. **ARM64 from the start.** The recompiled output uses SIMDe or NEON in
   place of x86-only intrinsics, so ARM never needs retrofitting.
5. **Targets:**
   - Windows x86-64 first, then Linux and Steam Deck.
   - Then an Anbernic handheld, chosen by profiling the PC build.
   - On specs, the RG35XX H (4× A53 at 1.5 GHz, Mali-G31 MP2, 1 GB) is
     likely too weak, while a higher-end Android Anbernic is plausible.
   - Low-end devices use UE3's own scalability settings (resolution, shadows,
     post-processing, LOD).
6. **What users need:** their own copy of the build's game files. The repo
   ships none.

### Track 2: n-Space's C++ (matching decomp)

- **Scope:** the 1,258 `nspace` rows. Epic's UDKBase and GameFramework code
  stays recompiled.
- **Done for a function:** XDK 21076 `cl`, run with the PDB's flags for its
  object, produces the same bytes, with relocated fields masked. Phase 0
  matched 10 of 10.
- **Matching bar:** match where it comes cheaply. Time-box near-misses (mark
  them `near` with the suspected cause). Use `equivalent` for a function
  verified in the port.
- **Markers:** `// @object <obj>` once per file, and `// @retail 0x82xxxxxx`
  before each function. Matched functions can replace their recompiled
  versions in the port.

### Track 3: UnrealScript

- **Export:** every package exports (2,571 of 2,597 classes clean).
- **Committed:** the `nspace-only` and `modified` classes, under
  `script/<Package>/Classes/`.
- **Left out:** the 1,839 classes identical to UDK's. UDK July 2012 BETA 2
  ships them, and `config/script_classes.csv` lists every class with its status.
- **To check later:** UDK July 2012 BETA 2 has the same engine version, so its
  script compiler may be able to rebuild and check n-Space's scripts.

### Not doing

- Hand-decompiling the engine or the middleware.
- Using leaked UE3 source.
- Copying GPL code into the CC0 tree. GPL projects (for example
  UnleashedRecomp) are used for ideas only. BSD and MIT code (Xenia,
  XenonRecomp) may be used with its notices kept.

## Phases

0. **Feasibility.** Done. Gates A and C passed. Gate B passed on the corrected
   count (+0.76% over PDB procedures plus public-only functions), with the
   jump tables and missing instructions carried into Phase 2.
1. **Public launch.** See `docs/plans/2026-10-18-phase1-launch.md`. Slim the
   inventory, commit the script export, write the docs, and set up CI and
   discoverability. Then publish a squashed history.
   - recomp.fyi: `.recomp.json`, plus a submission if the site needs one.
   - ByteMatch (decomp.dev's successor): the report workflow; the project is
     registered with the GitHub app installed (https://bytematch.dev/kirklandsig/halo-mega-bloks-decompiled).
2. **Port to PC.** Done (`docs/specs/phase2-baseline.md`). Upstream Xenia
   reaches gameplay with `console_type = 0`. The port is built on the ReXGlue
   SDK (BSD), found in the prior-art search, in place of a XenonRecomp fork
   and a hand-written Xenia CPU backend. Results:
   - our jump-table detector, 345 tables;
   - no unimplemented instruction;
   - a full compile;
   - on Windows, M5: the first level is playable, at 11 to 16 fps on an
     integrated GPU.
   Left over:
   - Linux builds and starts UE3, but on a software Vulkan device it asserts
     before the first frame. Real GPUs and the Steam Deck are untested;
   - the packaged Xenia build wasn't compared (antivirus quarantine);
   - the frame rate on a discrete GPU isn't measured.
3. **n-Space's C++.** Done (`docs/PROGRESS.md`). 875 of the 1,258 `nspace`
   rows match, 4 are near, 379 are todo, mostly from generators
   (`tools/gen_header.py`, `tools/gen_classes.py`). The port-swap spike
   (`docs/specs/phase3-port-swap.md`) builds one source both ways and hooks
   it into the port; recommendation: use it only for code worth modding, and
   keep the port fully recompiled otherwise. UDK July 2012 BETA 2's script
   compiler builds UDK's packages, and n-Space's Engine additions and AkAudio;
   Grip stops on a lost `dependson`.
4. **Handheld.** Profile, then build the native renderer and the ARM64 build,
   then tune scalability, then run on the chosen Anbernic.

## Risks

- **GPU and runtime work dominates Phases 2 and 4.** With one lane it will
  take a while.
- **XenonRecomp** needs a fork for this compiler. The PDB keeps that bounded.
- **UE3 header inlines** (`TArray`, `FString`) must be right before many game
  functions can match. Vector (VMX128) matching is untested.
- **Handheld performance** is unknown until the PC build can be profiled.
